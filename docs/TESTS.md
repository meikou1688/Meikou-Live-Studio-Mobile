## 實機驗收紀錄方式

先開啟「檢視手機硬體參數」並複製清單，記錄手機型號、Android／韌體版本、公開 ID、實體 ID 與等效焦距。將 INSTA360 MIC PRO 接收器插入手機後選取實際裝置，先測 720p30，再測 1080p30；每種設定保留錄影。於三個焦段輪流遮住對應鏡頭，對照預覽、接收端影像及作用中 ID，記錄停格時間、收音連續性與是否中斷連線。若系統只提供數位裁切，該焦段記為未證實實體切鏡。

USB 基準驗收可在一般 Windows 開發環境執行 tools/device_check.ps1，使用 USB 轉接 TCP、私人本機接收器與暫存測試網址，實際安裝 APK 並解碼手機推來的檔案。此項只測 USB 路徑。再用私人 RTMPS 接收端分別測單一 5G 與 Speedify 雙線聚合，於同一場測試中拔除一路、恢復連線及手動停止重連。記錄接收端時間軸、編碼器、音畫差、網路斷線與復原時間。Android 顯示 VPN 僅代表網路路由，仍需 Speedify 的連線統計佐證多卡確實承載流量。

正式現場使用的驗收條件包含三鏡實際視角、外接收音、連續直播、接收端可解碼、長時間影音同步、儲存空間與熱穩定性。此版未取得這些手機端驗收結果。

## 0.1.5 推流欄位與接收測試

RTMP 與 RTMPS 的分欄、完整網址、查詢參數保留與錯誤格式共 13 組測試通過。GitHub Actions 執行編號 45858522474 以應用程式共用 Kotlin 發布程式及測試用金鑰連至接收端；RTMP 與經 TLS 的 RTMPS 都解出 90 個 H.264 影格及 142 個 AAC 音訊框。TLS 端點使用測試專用憑證，信任設定限於測試用 JVM。來源為三秒測試影音；尚未在 VIVO 驗證橫式觸控、實體長焦及平台實播。
